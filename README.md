# حسابداری من — مدیریت اشخاص، فاکتورها و پرداخت‌ها

وب‌اپلیکیشن کاملاً محلی (بدون نیاز به اینترنت) برای مدیریت **اشخاص**، **فاکتورها** و **پرداخت‌ها** با دیتابیس **SQLite** داخلی.

---

## پیش‌نیاز

- **Node.js نسخه ۲۲.۵ یا بالاتر** — دیتابیس داخلی `node:sqlite` از این نسخه به بعد موجود است  
  بررسی با: `node --version`

## اجرای سریع

```bash
node --disable-warning=ExperimentalWarning server.js
```

سپس در مرورگر باز کنید: **http://localhost:3000**

(یا به‌جای دستور بالا: `npm start`)

- در اولین اجرا، دیتابیس **تمیز** ساخته می‌شود: فقط تنظیمات پیش‌فرض (واحد پول ریال، مالیات ۱۰٪ و …) — جدول اشخاص/فاکتورها/پرداخت‌ها خالی است.
- **کاربر نهایی** به هیچ پیش‌نیازی نیاز ندارد — فقط فایل‌های برنامه را اجرا می‌کند.

## امکانات

- **داشبورد**: آمار کل (اشخاص/فاکتورها، فروش/خرید، دریافتی/پرداختی) + **حساب شرکت** (دریافتی، پرداختی، موجودی) + **بستانکارها — پیشنهاد تسویه** با دکمه‌ی «همه بدهکاری / بستانکاری‌ها» + نمودار روند ۶ ماهه + آخرین فاکتورها و تراکنش‌ها
- **اشخاص**: جدول کامل با جستجو، افزودن/ویرایش/حذف، همه فیلدهای درخواستی (کد ملی، کد اقتصادی، شماره بانکی و …)
- **فاکتورها**: نوع خرید (پیش‌فرض)/فروش، تاریخ شمسی، «طرف حساب» با برچسب هوشمند (فروشنده/تأمین‌کننده برای خرید، خریدار/مشتری برای فروش) و **انتخاب‌گر اشخاص**، اقلام چندردیفه با محاسبه خودکار (جمع، تخفیف، ارزش افزوده)، **دکمه محاسبه خودکار ارزش افزوده** بر اساس درصد تنظیم‌شده در تنظیمات، ستون **مانده فاکتور** و بخش **پرداخت‌های فاکتور** (یک فاکتور می‌تواند توسط چند شخص پرداخت شود)
- **پرداخت‌ها (دریافت / پرداخت)**: نوع انتقال (نقدی، چک، حواله، کارت به کارت، پایا، ساتنا و …)، مبلغ و تاریخ شمسی + **انتخاب فاکتور** — اگر تراکنش بابت یک فاکتور باشد، انتخابش می‌شود تا از مانده‌ی فاکتور کسر و حساب طرفین به‌درستی به‌روزرسانی شود
- **انتخاب‌گر اشخاص (مثل نرم‌افزارهای حسابداری)**:  
  - تایپ شناسه → بارگیری خودکار اطلاعات شخص  
  - دکمه انتخاب‌گر → پنجره جستجو با کلیک روی ردیف  
  - دکمه «افزودن شخص جدید» داخل همان پنجره در صورت نبودن شخص
- **گزارش‌ها**:  
  - گزارش یکپارچه همه اقدامات اشخاص (فاکتور خرید/فروش + دریافت/پرداخت) با فیلتر **بازه تاریخ**، **نوع** و **شخص** (کشوی جستجوی شخص با فیلتر زنده و دکمه‌ی حذف فیلتر) — با انتخاب شخص، **مانده‌ی جاری حساب** (بدهکار/بستانکار) روی هر ردیف نمایش داده می‌شود  
  - تب **«اشخاص (مانده حساب)»**: بدهکاری/بستانکاری همه‌ی اشخاص (بدهکار، بستانکار، مانده) مثل نرم‌افزارهای حسابداری  
  - **گزارش تفصیلی هر شخص** (دابل‌کلیک روی ردیف): همه‌ی تراکنش‌های شخص به ترتیب تاریخ با مانده‌ی جاری، قابل **چاپ** و **خروجی اکسل (CSV)**  
  - دابل‌کلیک روی هر ردیف → باز شدن فرم فاکتور/پرداخت برای مشاهده و ویرایش
- **منوی راست‌کلیک سفارشی** (منوی پیش‌فرض مرورگر غیرفعال است):  
  - در **اشخاص**: فاکتور جدید، دریافت/پرداخت جدید، گزارش فاکتورها، مانده حساب  
  - در **فاکتورها**: مشاهده/ویرایش/چاپ، **ثبت پرداخت / دریافت برای فاکتور**، **تسویه مانده** (باز شدن فرم پرداخت با مبلغ مانده)، گزارش فاکتورهای شخص  
  - در **پرداخت‌ها**: ویرایش تراکنش، گزارش تراکنش‌های شخص  
  - در **گزارش‌ها**: ویرایش رکورد، مشاهده/ویرایش شخص، ثبت فاکتور/دریافت/پرداخت جدید — همه به‌صورت **مودال**without خروج از صفحه فعلی
- **تنظیمات**: درصد مالیات ارزش افزوده (پیش‌فرض ۱۰٪)، واحد پول (پیش‌فرض ریال)، اطلاعات شرکت برای چاپ، **پشتیبان‌گیری خودکار** با بازه دلخواه، **مسیر سفارشی پشتیبان** (با هشدار درباره درایو ویندوز)، **رمز بازیابی** برای امنیت بازگردانی
- **حالت روز/شب** با ذخیره خودکار انتخاب
- **کاملاً ریسپانسیو**: در موبایل منوی کشویی (Drawer)، جدول‌ها اسکرول‌شونده
- اعداد فارسی/سه‌رقمی، تاریخ شمسی (جلالی)، محافظت از حذف اشخاصی که فاکتور/پرداخت دارند

## ساختار پروژه

```
├── server.js            ← سرور HTTP (API + سرو فایل‌های استاتیک)
├── server/db.js         ← اسکیمای SQLite + داده‌های نمونه
├── client/
│   ├── index.html
│   ├── css/styles.css   ← طراحی سیستم (تم‌ها، ریسپانسیو، انیمیشن)
│   ├── js/              ← منطق سمت کلاینت (بدون فریم‌ورک)
│   └── fonts/           ← (اختیاری) فونت وزیرمتن — توضیحات داخل پوشه
├── build/
│   ├── electron-main.cjs    ← پروسه اصلی Electron (پنجره مستقل + اجرای سرور)
│   ├── lib-bundle.cjs       ← تبدیل ESM سرور به CJS برای بسته‌بندی
│   ├── build-electron.cjs   ← اسکریپت ساخت exe (electron-packager)
│   ├── make-icon-user.py    ← تبدیل PNG آیکون کاربر به ICO (Pillow)
│   ├── icon.ico             ← آیکون برنامه (از تصویر کاربر)
│   └── installer/           ← فایل‌های ساخت Setup (hesab.iss + Farsi.isl + icon)
├── dist/                ← خروجی نسخه دسکتاپ: x64 و ia32 + zip + HesabSetup.exe
└── data/hesab.db        ← دیتابیس SQLite (به‌صورت خودکار ساخته می‌شود)
```

## فونت (اختیاری)

برنامه با فونت‌های سیستمی (Segoe UI / Tahoma) فارسی را خوب نمایش می‌دهد. برای ظاهر بهتر، فایل‌های فونت **Vazirmatn** را در پوشه `client/fonts/` قرار دهید — نام فایل‌ها را در `client/fonts/README.txt` ببینید.

## نسخه دسکتاپ (exe) — بدون مرورگر

برنامه به یک **اپلیکیشن دسکتاپ مستقل (Electron)** تبدیل شده است: سرور به‌صورت داخلی اجرا و برنامه در یک **پنجره‌ی مستقل** باز می‌شود — کاربر نیازی به مرورگر ندارد.

- **دو نسخه** ساخته می‌شود:
  - `dist/hesab-win32-x64/hesab.exe` — ۶۴ بیتی (zip: `dist/hesab-desktop-x64.zip`)
  - `dist/hesab-win32-ia32/hesab.exe` — ۳۲ بیتی (zip: `dist/hesab-desktop-ia32.zip`)
- **داده‌ها** در `%APPDATA%/hesab/` ذخیره می‌شوند (دیتابیس + پشتیبان‌ها + `server.log`)
- سرور فقط روی `127.0.0.1` گوش می‌دهد و امن است؛ پنجره نمی‌گذارد کاربر از برنامه به سایت‌های دیگر برود
- تک‌نمونه: اگر برنامه از قبل باز باشد، دوباره باز نمی‌شود و فقط پنجره‌ی قبلی جلو می‌آید
- اگر پورت ۳۰۰۰ گرفته باشد، به‌صورت خودکار پورت آزاد پیدا می‌کند
- آیکون برنامه از تصویر PNG کاربر ساخته می‌شود: `python build/make-icon-user.py`

### فایل نصب (Setup)

یک فایل نصب واحد برای هر دو معماری ساخته می‌شود: `dist/HesabSetup.exe` (حدود ۱۹۵MB).

- روی **ویندوز ۶۴ بیتی** نسخه‌ی x64 و روی **ویندوز ۳۲ بیتی** نسخه‌ی ia32 به‌صورت خودکار نصب می‌شود
- **مسیر پیش‌فرض**: `Program Files\Hesab` — کاربر می‌تواند در هنگام نصب محل نصب را تغییر دهد
- میانبر روی **دسکتاپ** و **منوی استارت** ساخته می‌شود
- نصب **نیاز به دسترسی مدیر (UAC)** دارد
- **نصب مجدد (بروزرسانی)**: اگر برنامه از قبل روی سیستم نصب باشد، پس از انتخاب زبان، صفحه‌ای با سه گزینه نمایش داده می‌شود: **بروزرسانی** (نصب در همان محل قبلی، بدون تغییر مسیر)، **حذف برنامه** (اجرای حذف‌کننده موجود) و **انصراف**. اگر برنامه نصب نباشد، مراحل معمول نصب با انتخاب محل نصب انجام می‌شود.
- برنامه پس از نصب قابل اجرا از میانبر است؛ حذف نصب از کنترل پنل — **داده‌های کاربر (دیتابیس و پشتیبان‌ها) هنگام حذف نصب پاک نمی‌شوند**

ساخت فایل نصب:

```bash
npm run build:setup   # بعد از ساخت هر دو نسخه (npm run build:exe)
# یا مستقیم:
"C:/Program Files (x86)/Inno Setup 6/ISCC.exe" build/installer/hesab.iss
```

### ساخت نسخه دسکتاپ

```bash
npm install          # فقط بار اول (Electron)
npm run build:exe   # ساخت هر دو نسخه (x64 و ia32) با آیکون فعلی
```

خروجی در `dist/` ساخته می‌شود. برای توسعه‌ی سریع با پنجره: `npm run start:desktop`

### اجرا در حالت وب (توسعه)

```bash
npm start            # یا: node --disable-warning=ExperimentalWarning server.js
# سپس http://localhost:3000
```

## API (برای توسعه)

| متد      | مسیر                | توضیح                                                           |
|----------|--------------------|----------------------------------------------------------------|
| GET/POST | `/api/people`      | لیست/ایجاد اشخاص                                               |
| GET/PUT/DELETE | `/api/people/:id` | خواندن/ویرایش/حذف شخص                                       |
| GET/POST | `/api/invoices`    | لیست/ایجاد فاکتور (با اقلام)                                   |
| GET/PUT/DELETE | `/api/invoices/:id` | خواندن/ویرایش/حذف فاکتور                                   |
| GET/POST | `/api/payments`    | لیست/ایجاد تراکنش                                               |
| GET/PUT/DELETE | `/api/payments/:id` | خواندن/ویرایش/حذف تراکنش                                   |
| GET      | `/api/stats`       | آمار داشبورد                                                    |
| GET      | `/api/ledger`      | گزارش یکپارچه (فاکتورها + دریافت/پرداخت + مانده اشخاص با `kind=persons`) با فیلتر از/تا/شخص/نوع — با `person_id` مانده‌ی جاری هر ردیف نیز محاسبه می‌شود |
| GET      | `/api/settings`    | تنظیمات (واحد پول، درصد مالیات، مسیر پشتیبان و …)            |
| GET/POST | `/api/backups`     | لیست / ایجاد نسخه پشتیبان                                      |
| POST     | `/api/backups/restore` | بازیابی از پشتیبان (با بررسی رمز در صورت تنظیم)             |
| DELETE   | `/api/backups/:file` | حذف نسخه پشتیبان                                              |
